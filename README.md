# hoopcv：篮球技术动作视觉分析

用手机视频测投篮和突破的关节角度、内外旋、出手角和突破方向。底层是 MediaPipe 姿态估计 + 可选的 YOLO 篮球检测，输出 CSV、图表、带骨架标注的视频和中文报告。

单机位能用；两部手机同时拍时，`hoopcv stereo` 会自动对齐时间、自标定两台相机、三角化出真实 3D，内外旋不再是近似值。

## 安装

```bash
cd hoopcv
pip install -e .            # 基础功能
pip install -e ".[ball]"    # 加上篮球检测（会装 PyTorch，体积较大）
```

第一次运行会自动下载 MediaPipe 模型到 `~/.cache/hoopcv`（约 30 MB）。

## 四个命令

### 1. 逐帧关节角度

```bash
hoopcv angles 投篮.mp4 --side right
```

输出 `angles.csv`（每帧所有角度）、`angles.png`（曲线）、`annotated.mp4`（骨架 + 实时角度）。

### 2. 投篮分析

```bash
hoopcv shot 投篮.mp4 --side right --ball --made 1,0,1,1,0
```

- 自动切出每次投篮，标出下蹲最低点（dip）、举球到位（set）、出手（release）、随挥（follow）。
- `--ball`：检测篮球，拟合出手后的抛物线，得到**出手角**和**出手速度**（用重力加速度自动换算像素/米，不需要标定）。不加 `--ball` 时不报出手角。
- `--made`：按顺序填每球是否命中，报告里会多出“进球 vs 不进”对比，按效应量排出差异最大的指标。
- 还会给出动力链：膝、髋、肩、肘、腕的角速度峰值先后顺序和时间。

输出 `shots.csv`、`report.md`、`angles.png`、`annotated.mp4`。

### 3. 突破分析

```bash
hoopcv drive 突破.mp4 \
  --court-px "412,610;868,604;1010,890;270,900" \
  --court-m  "-2.45,5.8;2.45,5.8;2.45,0;-2.45,0" \
  --basket   "0,1.575"
```

- `--court-px` / `--court-m`：画面里 4 个已知球场点的像素坐标和对应的球场坐标（米），用于把脚的位置投到地面。上例是罚球线两端和禁区底角（FIBA 尺寸：禁区宽 4.9 m、罚球线距底线 5.8 m、篮筐中心距底线 1.575 m；原点在底线中点，y 指向场内）。像素坐标可以用任意看图软件读。
- `--basket`：篮筐在球场坐标中的位置；突破角 = 起步方向（启动后约前两步）相对“起点→篮筐”方向的偏角，在你给的球场坐标系里逆时针为正。
- 不给标定也能跑，但距离单位变成“身高”，方向角只在高处俯拍或正后方机位时可信。

输出 `drive.json`（启动时刻、突破角、第一步是左/右脚、交叉步/顺步、步长、重心下降、躯干前倾/侧倾、峰值速度）、`cuts.csv`（每次变向的切角、速度、侧倾、膝角）、`track.png`、`annotated.mp4`。

### 4. 双机 3D（推荐用于内外旋）

```bash
hoopcv stereo 手机A.mp4 手机B.mp4 --task shot --focal-a 1450 --focal-b 1450 --height 1.83 --fps 240 -o 输出目录
```

手机 A 是参考机，拍侧面（90°），必须保持水平；手机 B 放在斜前方 45° 左右。流程：

1. **时间对齐**：先用两段视频的声音（开拍时拍一下手，运球声也行）做互相关，精度约 1 ms；没有声音或置信度低时，改用两机里关节竖直运动的互相关。两种方法相差超过 2 帧会警告。也可以 `--offset 0.073` 手动指定 B 比 A 晚多少秒。
2. **相机标定**：默认不需要标定板，把球员身体当标定物：用两机同时看到的关键点估本质矩阵，再用重投影误差 + 骨长一致性约束精修相机位姿和焦距。尺度按 `--height`（球员身高）换算，只影响距离和速度，不影响角度。画面里有已知球场点时，加 `--court-m`、`--court-a`、`--court-b`（各 ≥ 4 个点、顺序一致）得到球场坐标系下的米制 3D。
3. **三角化**：逐帧加权三角化，重投影误差过大的点（遮挡、左右腿认反）丢弃，之后的角度计算、投篮切分、突破分析和单机版完全一样，只是 3D 列换成了真实 3D。

`--task` 选 `shot`（默认）、`angles` 或 `drive`，其余参数与单机命令相同。B 机的 `--fps-b`、`--rotate-b` 单独设置。

输出（在单机输出之外）：

| 文件 | 内容 |
| --- | --- |
| `stereo.json` | 对齐结果（方法、偏移、置信度）、两台相机的内外参、重投影误差、提示 |
| `skeleton3d.json` | 给 app 的逐帧 3D 骨架，单位米，three.js 约定（x 右、y 上、z 指向手机 A），含关节名和连线 |
| `angles.csv` | 3D 列为双机结果；另有 `*_mono` 列是手机 A 单目的同一指标，方便对照单机误差 |

### 给 app 的拍摄与对接要求

- 两台手机同时开录，**开拍后拍一下手**；录完把两段视频（原始文件，不要剪辑）一起上传。
- 手机 A 用水平仪保持水平（重力方向取 A 的竖直方向）；两机夹角 ≥ 30°，距离 4-6 m，都用 1× 主摄，关闭防抖和自动变焦。
- app 从系统相机内参读焦距（iOS 打开 `AVCaptureConnection.isCameraIntrinsicMatrixDeliveryEnabled` 让每帧带内参矩阵，或按 `AVCaptureDevice.Format.videoFieldOfView` 换算；Android 用 `LENS_INTRINSIC_CALIBRATION`，或 `LENS_INFO_AVAILABLE_FOCAL_LENGTHS` + `SENSOR_INFO_PHYSICAL_SIZE` 换算），换算到导出视频的分辨率后传 `--focal-a/--focal-b`。不传也能跑，焦距会被一并估计，但误差略大。
- 开始投篮前，球员原地转半圈、抬一下手臂，能让自标定更稳。
- 慢动作视频传真实帧率（`--fps`），两台的慢动作倍率最好一致，否则只能用动作互相关对齐。

## 通用参数

| 参数 | 作用 |
| --- | --- |
| `--side right/left` | 分析哪一侧（投篮手） |
| `--fps 240` | **慢动作视频必填**：手机导出的慢动作常被标为 30 fps，不改的话所有时间和速度都错 |
| `--rotate 90` | 竖拍视频方向不对时旋转 |
| `--model lite/full/heavy` | 姿态模型，默认 heavy（最准、最慢） |
| `--reuse` | 复用已算好的 `pose.npz`，改参数重跑时省时间 |
| `--no-video` | 不输出标注视频 |
| `--cutoff 8` | 低通滤波截止频率（Hz），动作越快可以设越高 |

## 指标说明

| 列名 | 含义 | 可靠性 |
| --- | --- | --- |
| `*_flex_2d` | 肘/膝/髋/腕屈曲角，伸直 = 0 | 正侧面机位下可靠；与 chonyy/AI-basketball-analysis 在同一段投篮上对照，差 0-4° |
| `shoulder_flex_2d` | 上臂与躯干夹角 | 同上 |
| `trunk_lean_2d` | 躯干前倾（朝面向方向为正） | 同上 |
| `shoulder_elev_3d`、`shoulder_plane_3d` | 上臂抬高角与抬高平面（0 = 侧平举，90 = 前平举） | 单目 3D，中等 |
| `shoulder_ext_rot_3d` | 肩外旋（+）/ 内旋（−），以“前平举、前臂朝上”或“手臂下垂、前臂朝前”为 0 | 单机：近似，只看同一人多次之间的趋势；双机：合成数据误差中位 0.5°；肘接近伸直（< 20°）时无定义 |
| `hip_ext_rot_3d` | 髋外旋（+）/ 内旋（−） | 同上（双机误差中位 0.8°），膝屈曲 < 20° 时无定义 |
| `forearm_pron_3d` | 前臂旋前（+）/ 旋后（−），握手位 = 0 | 粗略，MediaPipe 手指点精度有限（双机误差中位约 2°） |
| `trunk_lean_fwd_3d`、`trunk_lean_side_3d` | 躯干相对重力的前倾、向分析侧侧倾 | 假设相机水平 |

内外旋的计算参照 ISB 肩关节推荐：在躯干坐标系下做 Y-X-Y 欧拉分解，轴向旋转取第一、三角之和以消除抬高平面的耦合。

## 拍摄建议

- **投篮**：投篮手一侧的正侧面，机位与胸同高、距离 4-6 m，球框和出手点都在画面内；尽量 120-240 fps。只拍一个人。
- **突破**：高处斜后方或正后方固定机位，60 fps 以上，画面里能看到 4 个已知球场点。
- **内外旋要准**：两部手机同步拍，用 `hoopcv stereo`（见上文拍摄要求）。

## 验证情况

- `tests/` 里 28 个测试：几何定义（各种肩/髋/前臂姿势的已知角度）、用已知运动学合成的投篮（出手角 52°、出手速度 7 m/s 能还原到 ±1°、±5%）、合成的突破（突破角、交叉步、60° 变向）。运行：`pip install pytest && pytest`。
- 在 chonyy/AI-basketball-analysis 的示例投篮片段上，本工具的肘角、膝角与该项目（OpenPose）叠加显示的数值相差 0-4°。
- 篮球检测（`--ball`）的拟合逻辑在合成数据上测过，整条流程在真实片段上能跑通。但在那段 10 fps、球很小的示例 GIF 上，COCO 通用 YOLO 只在 13% 的帧里找到球，不够拟合出手角。实际使用请拍 60 fps 以上、球在画面里足够大的视频；仍然检不到时，换篮球专用权重（`--ball-weights`，`--ball-class`）。
- 双机 3D 在合成数据上验证（已知 3D 动作 + 两台虚拟手机，1 px 关键点噪声、2% 丢点、焦距初值偏 10%）：时间对齐误差 < 半帧；自标定后两机相对旋转误差约 0.3°；关节角与真值的中位误差为肘 0.4°、膝 0.3°、髋屈 0.3°、肩抬高 0.2°、肩内外旋 0.5°（p90 1.7°）、髋内外旋 0.8°、前臂旋前 2.2°、躯干前倾 0.1°。球场标定模式 3D 位置误差 < 3 cm。**还没有在真实双机视频上验证**，真实 MediaPipe 关键点噪声比合成数据大，误差会更大，需要拿 Vicon 或 OpenCap 做一次对照。
